MoneyBook 基金模組 — 實作規劃

2026-09-06 擬定 · 基準版本 v1.14.0 · 狀態：階段 1–4 已完成（v1.15.0）

0. 需求

  1. 基金要能像股票一樣看到成本與報酬率
  2. 台幣計價與外幣計價的基金都要能記
  3. 股票與基金分開管理，但都計入總資產

債券不在這一版：手上若是債券 ETF（00679B、00687B 等），現有股票模組已經能記， 代號清單裡就有；直接持有的海外債另議（見第 7 節）。

1. 三個架構決策

1.1 基金自成一個模組，不共用股票的引擎

新寫 js/lib/funds.js，不改 portfolio.js。理由：

  • portfolio.js 強制 Number.isInteger(shares) —— 台股本來就是整數股，這個限制是一層防護，不該為了基金拆掉
  • 單位語意不同：股 vs 單位、股價 vs 淨值。 硬合併會讓兩邊的欄位名稱都變模糊，日後看不出哪個數字該是什麼
  • 現有 210 項測試有一大半壓在 portfolio.js 上，動它是純粹的回歸風險

共用的是算式不是檔案：加權平均、賣出時依比例攤提成本， 兩邊各自實作同一套邏輯，各自有測試。

1.2 幣別只活在基金模組裡面

這是整份計畫最重要的一條。不要把幣別推進記帳、帳戶、統計、報表 —— 那些地方全部假設台幣，一旦引入幣別，每一個加總都要處理換匯，改動面積會失控。

基金部位自己帶幣別，估值時換成台幣，對外只吐台幣市值。 邊界跟股票模組一樣是「市值（台幣）→ 寫回綁定帳戶」，這條邊界 v1.14.0 已經驗證可行。

1.3 成本記原幣＋當時匯率，不記台幣總額

外幣基金的「報酬率」有兩個都正確但不同的答案：

算法回答的問題誰在用
原幣報酬率這檔基金本身績效如何基金公司對帳單
台幣報酬率我到底賺了多少台幣你真正在意的

差額就是匯兌損益。只存台幣總成本會永久失去算出原幣績效的能力； 存「原幣金額 ＋ 申購當日匯率」則兩個都算得出來。多存一個數字換不可逆的資訊，划算。

2. 資料模型

沿用「部位由交易推算、不存第二份」的原則。IndexedDB 新增一個 fundTrades store：

{
  id, date,
  fundId,     // 使用者自訂代碼（基金沒有像股票代號那樣的全民統一編號）
  name,       // 基金全名
  currency,   // 'TWD' | 'USD' | 'CNY' | ...
  action,     // opening | buy | sell | dividend | reinvest
  units,      // 單位數 × 10^4（4 位小數）
  nav,        // 每單位淨值 × 10^4（原幣）
  fxRate,     // 交易當日匯率 × 10^6（原幣→台幣）；台幣基金固定 1000000
  fee,        // 手續費（原幣，分）
  amount,     // 配息金額（原幣，分）
  note, createdAt
}

2.1 部位彙總

每檔基金累加三個數字，賣出時三個一起依比例攤：

欄位意義
units目前持有單位數
totalCostForeign原幣總成本（分）
totalCostTWD台幣總成本（分）＝ Σ 每筆的 units × nav × 當時匯率

2.2 數值精度：一個會靜靜爆掉的陷阱

單位數與淨值若都存成高倍數整數再直接相乘，會超出 JavaScript 安全整數範圍。 以 10 萬單位、淨值 15 美元為例：若 units 用 104 倍、nav 用 106 倍， 乘積約 1.5 × 1016，已經大於 Number.MAX_SAFE_INTEGER（約 9 × 1015）。 從那一刻起數字會開始無聲地失真。

因此：units 與 nav 各存 104 倍整數，相乘時先還原成一般數值， 結果立刻 Math.round 成「分」的整數再累加。 中間過程容許浮點、結果一律落回整數 —— 這與現有 「totalCost 是整數分、avgCost 只是顯示用浮點」是同一種紀律。

同樣的界線要寫成測試：極端值（千萬單位 × 淨值 1000）必須仍在安全範圍內。

3. 匯率怎麼來

先手動維護，跟現在的股價一樣。設定裡存一張表： 

fxRates: { USD: 32500000, CNY: 4520000 }   // × 10^6
沒有匯率就不計入，絕對不能預設 1.0。 把 10 萬美元當成 10 萬台幣，畫面上會是一個看起來很正常、實際上錯了 32 倍的數字 —— 這正是整個專案一路在避免的那種錯法。缺匯率的部位比照缺股價處理： 算不出台幣市值就標示「N 檔缺匯率，未計入」。

自動抓匯率留到之後，跟股票的 FinMind 自動抓價同一階段做（同樣預設關閉）。

4. 總資產怎麼併進去

沿用 v1.14.0 的綁定機制，但股票與基金各綁各的帳戶：

模組設定鍵建議帳戶
股票投資stockAccountId證券帳戶
基金投資fundAccountId基金帳戶

兩個都是「手動估值」帳戶，都進淨資產，但在資產頁是兩個獨立區塊、兩份持股清單。 一個數字仍然只有一個來源，也不會互相干擾。

既然綁定機制現在要服務兩個模組，syncStockValueToAccount() 會改寫成 以模組為參數的通用版本，避免兩份幾乎相同的程式各自長歪。

5. 介面

5.1 定期定額會把列表撐爆

一檔基金扣款三年就是 36 筆買進。列表預設只顯示部位彙總 （單位數、平均成本、現值、報酬率），點開才展開交易明細 —— 與現在股票區塊的做法一致。

5.2 每檔要顯示的數字

  • 單位數、平均成本（原幣）、目前淨值
  • 市值（台幣）
  • 原幣報酬率 與 台幣報酬率兩個都給，差額即匯兌損益
  • 台幣基金只顯示一個報酬率，不必為了整齊硬塞兩個一模一樣的數字

7. 債券

目前的建議是先不做部位級的債券模組：

  • 債券 ETF（00679B 等）：現有股票模組已經完全支援，代號清單裡就有
  • 債券型基金：就是基金，走這份計畫
  • 直接持有的海外債：報價是面額的百分比、要算應計利息、到期自動還本 —— 每一項都是可能靜靜算錯的地方，而且散戶直接持有的門檻通常是 10 萬美元起。 先用「手動估值」帳戶記總額，真的有需要再單獨規劃

8. 待確認

  1. 基金要用什麼當識別碼？基金沒有像股票代號那樣的全民統一編號， 打算讓使用者自己取（例如「安聯台灣科技」），你也可以填基金統編
  2. 配息要記成現金入帳，還是配息再投資（轉成單位數）？兩種都會做， 想確認你手上以哪一種為主
  3. 手續費：台幣基金常見「申購手續費內扣」，要不要跟股票一樣併進成本？ （預設併進，與股票一致）
